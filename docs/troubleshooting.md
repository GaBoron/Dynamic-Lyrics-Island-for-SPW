# 故障排查

本文用于处理安装后最常见的显示、歌词、交互和平台问题。功能本身是否支持，请先查看 [兼容性与限制](compatibility.md)；设置项含义和日常操作见 [使用与设置](usage.md)。

## 先确认这几项

遇到问题时，建议先做以下检查：

1. 确认安装的是当前平台对应的插件 ZIP，并且插件已经在 SPW 中启用；安装方式见 [安装与更新](installation.md)。
2. 切换一次歌曲，必要时重启 SPW 后重新测试。
3. 歌词相关问题先确认 SPW 自己已经成功加载歌词。本插件只显示 SPW 已加载的歌词，不负责联网搜索歌词。
4. 如果只是找不到词岛，在 SPW 插件设置中点击“找回词岛”。
5. 如果问题只在特殊设置下出现，先恢复到 1× 播放速度、关闭实验性功能后再判断。

---

## 插件已经启用，但词岛完全不显示

依次检查：

- 正在播放的歌曲是否已经被 SPW 正常识别；
- “显示词岛”是否开启；
- 是否开启了“暂停时隐藏”；
- Windows 下是否开启了“全屏时隐藏”；
- 词岛是否被拖到其他屏幕或当前不可见区域。

最直接的恢复方式是打开 SPW 插件设置，点击“找回词岛”。该操作会重新显示词岛，并将位置恢复到主屏幕顶部；Windows 下同时会解除鼠标穿透。

`Ctrl+Shift+D` 也可以显示／隐藏词岛，但当前快捷键只在 SPW 内生效，不是系统全局快捷键。

如果 SPW 的插件列表中根本没有出现本插件，请重新检查安装包和安装位置，而不是继续排查词岛显示设置。

---

## 只有歌名，没有歌词

词岛可以在暂时没有歌词行时显示当前歌曲信息，因此“能看到歌名”不代表 SPW 已经把歌词传给插件。

请先确认 SPW 自己能够显示当前歌曲的歌词，然后：

1. 切换到另一首歌曲再切回来；
2. 如果使用其他歌词插件，确认它已经正常完成歌词加载；
3. 重新播放或重新加载当前歌曲后再观察。

本插件不会主动搜索网络歌词。如果希望自动补充逐字歌词，可以搭配 [SPW-Lyrics](https://github.com/GaBoron/SPW-Lyrics)。

部分宿主版本中，多个歌词插件同时工作时，回调顺序可能影响本插件能否收到对应歌词事件。这类情况如果能够稳定复现，请提交 Issue，并说明同时启用了哪些歌词相关插件。

---

## 歌词完全不出现，歌名也不正确

先切换一次歌曲。

插件启动时如果错过了 SPW 更早的曲目加载事件，会尝试恢复当前曲目信息；正常情况下不需要用户操作。如果切歌后仍然错误，请记录：

- 出问题的是本地歌曲还是网络歌曲；
- SPW 自己显示的曲目信息是否正确；
- 是否只有插件刚启用后的第一首歌出现问题；
- 切歌后能否恢复。

这些信息比单独截图更有助于判断是宿主回调还是插件状态问题。

---

## 逐字高亮偏早或偏晚

在 SPW 的插件设置中调整“逐字高亮偏移 ms”：

- 正值：高亮提前；
- 负值：高亮延后。

这个设置只修正逐字高亮的整体时间偏差。歌词什么时候切换到下一行仍主要由 SPW 提供的歌词时间决定。

如果不同歌曲需要完全不同的偏移量，更可能是歌词源本身的时间轴质量问题，而不是统一 offset 能解决的问题。

### 调整播放倍速后明显不同步

当前对 SPW 非 1× 播放速度的适配仍不完整，改变倍速后可能出现明显的歌词动画和时间轴不同步。

排查其他歌词时序问题时，请先恢复到 **1×** 播放速度。该问题已经单独记录，不能通过不断修改“逐字高亮偏移”可靠修复。

---

## 多行歌词显示异常

“实验性多行歌词”依赖比普通当前行显示更多的歌词时间轴信息，因此兼容性低于默认单行模式。

如果出现：

- 同时显示了不应该重叠的歌词；
- 间奏期间保留了错误的上一行；
- 某些歌曲正常、某些歌曲明显异常；

请先关闭“实验性多行歌词”确认默认单行模式是否正常。

只有实验模式异常时，提交 Issue 请尽量附上具体歌曲、歌词来源和能够复现问题的时间位置。

---

## 看不到专辑封面

插件只读取本地可访问的封面：

1. 音频文件内嵌封面；
2. 音频文件同目录下的：
   - `cover.jpg`
   - `cover.png`
   - `folder.jpg`
   - `folder.png`

网络歌曲、当前无法读取的本地文件、没有封面的歌曲会使用占位图，这是正常行为。

如果本地歌曲明确带有封面但插件仍无法显示，请确认 SPW 当前播放路径确实指向该本地文件，并换一首本地歌曲比较。

---

## 开启封面取色后颜色没有变化

歌词、背景和频谱的封面取色都依赖插件先成功读取本地封面。

如果当前显示的是占位图，取色会继续使用默认颜色。

另外，取色结果并不是简单读取封面中心像素。插件会优先选择占比较高的彩色区域，并尽量避开近黑和近白，因此结果可能与肉眼第一眼认为的“主色”略有不同。

---

## 展开后没有可用的播放进度条，或显示 `--:--`

可拖动进度条需要知道歌曲总时长。

当前总时长主要从本地音频文件读取，因此以下情况可能无法提供完整进度控制：

- 网络歌曲；
- 本地文件暂时不可读取；
- 音频标签／格式无法提供可靠时长。

这时歌词和基本播放控制仍可继续使用，但进度条会禁用或无法显示完整总时长。

如果只有某一种本地音频格式持续无法读取时长，请提交具体格式和样例信息。

---

## 实时频谱不动

### Windows

先确认当前两侧信息设置确实包含频谱，并且歌曲正在播放。

实时频谱需要：

- Windows build 20348 或更高；
- 可用的 .NET Framework 4.x 运行环境；
- 共享模式音频输出。

独占模式、ASIO 或其他绕过系统共享音频链路的输出方式可能无法被进程回环捕获。遇到这种情况请先切换到共享模式输出测试。

如果实时捕获无法启动，插件会安全回退到模拟频谱，并在当前插件生命周期内提示一次原因。歌词显示不会因为实时频谱不可用而停止。

### 低性能模式

低性能模式会主动停用实时音频捕获，改用轻量模拟频谱。这是设计行为，不是实时频谱故障。

### Linux

Linux 当前没有实现 SPW 进程实时音频频谱。具体平台差异见 [兼容性与限制](compatibility.md)。

---

## 词岛突然消失

先检查以下设置：

- “显示词岛”；
- “暂停时隐藏”；
- Windows 下的“全屏时隐藏”；
- Windows 下的“鼠标穿透”和“悬停自动隐藏”。

动态壁纸、桌面增强软件或某些覆盖整个屏幕的窗口可能被 Windows 判断为全屏窗口。如果关闭“全屏时隐藏”后词岛立即恢复，通常属于这类情况。

多显示器连接状态发生变化后，如果词岛位置异常，直接使用“找回词岛”恢复到主屏幕。

---

## 开启鼠标穿透后无法操作词岛

这是鼠标穿透的正常效果：鼠标事件会直接交给词岛下方的窗口。

可以通过以下任一入口恢复：

- SPW 插件设置 → “找回词岛”；
- 系统托盘菜单中关闭鼠标穿透；
- 托盘中的恢复／显示相关操作。

开启“悬停自动隐藏”后，鼠标进入词岛区域时词岛还会主动缩小隐藏，移开后恢复。该功能只在鼠标穿透启用时有意义。

---

## 右键菜单里找不到某个设置

右键／托盘菜单只保留经常切换的设置，不是完整配置页。

以下一类设置应到 SPW 的插件配置页调整：

- 最大宽度；
- 背景不透明度；
- 圆角大小；
- 歌词字体与字重；
- 封面取色；
- 背景播放进度样式；
- 其他低频设置。

菜单中没有出现某项设置通常不代表该功能被删除。

---

## 字体显示异常、缺字或自定义字体没有预期效果

默认歌词使用插件内置的 Noto Sans SC，不要求用户另外安装字体，并提供多档真实字重。

如果“歌词字体（可选）”留空，插件会直接使用内置字体。

指定系统字体后：

- 只影响歌词，不影响插件菜单等界面字体；
- 找不到该字体时会回退到内置字体；
- 自定义字体缺少某个字符时会使用内置字体补字；
- 自定义字体本身可能不支持所有字重，因此不同字重的视觉差异由该字体决定。

极少数字符如果连内置字体也没有收录，仍可能显示缺字框。

---

## 词岛卡顿或动画不流畅

先开启“低性能模式”测试。

低性能模式会降低刷新率，并关闭或简化部分持续性高成本效果，包括复杂逐字动画、实时音频捕获、部分过渡和可选歌词探测。

如果低性能模式下仍然明显卡顿，请在反馈时说明：

- 系统版本；
- SPW 版本；
- 插件版本；
- 是否开启实验性多行歌词；
- 是否只在展开、拖动、切歌或逐字歌词时卡顿；
- Windows 还是 Linux；
- 如果是 Linux，使用的桌面环境以及 X11 / Wayland 情况。

“整个 SPW 都卡”和“只有词岛动画掉帧”是两类不同问题，反馈时请尽量区分。

---

# Linux

Linux 版本仍属于实验性支持，部分 Windows 功能不会出现。完整能力差异见 [兼容性与限制](compatibility.md)。

## 词岛上右键没有菜单

当前 Linux 快捷设置入口在系统托盘中，词岛区域右键暂不提供菜单。

请使用：

- Linux 系统托盘菜单；或
- SPW 原生插件配置页。

这不是右键事件失效。

---

## Linux 看不到托盘图标

插件优先使用 AppIndicator / Ayatana AppIndicator，无法使用时会尝试 GTK 传统托盘。

部分桌面环境默认没有可见的传统托盘区域，或者需要额外启用 AppIndicator 支持。这种情况下即使词岛本身正常，也可能看不到托盘图标。

托盘不可用不会阻止基本歌词显示。仍可以通过 SPW 的插件配置页管理插件。

提交此类问题时，请注明：

- Linux 发行版；
- 桌面环境；
- X11、XWayland 或 Wayland；
- 是否安装／启用了 AppIndicator 支持。

---

## Linux 拖动松手时短暂闪回旧位置

这是当前已知问题。

移动词岛后松开鼠标时，界面可能非常短暂地回到旧位置，再跳到刚保存的新位置。最终位置正确时不需要手动修复。

如果最终位置也保存错误，或者每次刷新都会反复跳动，则属于不同问题，请单独反馈。

---

# 仍未解决时如何反馈

提交 Issue 前，尽量确认问题可以重复出现，并附上足够判断问题来源的信息。

至少建议提供：

- Windows / Linux 及具体系统版本；
- SPW 版本；
- Dynamic Lyrics Island for SPW 版本；
- 使用的插件包平台；
- 清晰的复现步骤；
- 预期行为和实际行为；
- 截图或短视频（适合界面、动画和位置问题）；
- 出现的错误提示原文。

根据问题类型，再补充：

- **歌词问题**：歌曲、歌词来源、是否逐字歌词、是否启用实验性多行、播放倍速；
- **频谱问题**：Windows build、音频输出模式、是否出现 .NET／频谱回退提示；
- **封面问题**：本地／网络歌曲、音频格式、封面是内嵌还是同目录图片；
- **Linux 问题**：发行版、桌面环境、显示协议和托盘实现；
- **多屏／窗口问题**：显示器数量、缩放比例以及问题发生在哪块屏幕。

不需要在无法取得日志时专门制造日志；稳定的复现步骤通常比大量无关信息更有价值。
