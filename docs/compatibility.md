| 平台 | 状态 | 说明 |

## 歌词与 SPW 宿主边界

本插件只显示 **SPW 已经加载的歌词**。

它不会：

- 自己联网搜索歌词；
- 上传歌词；
- 修改歌曲文件；
- 修改外置歌词文件。

如果需要自动获取逐字歌词，可以搭配 [SPW-Lyrics](https://github.com/GaBoron/SPW-Lyrics)。

### 当前歌词与完整歌词轴

SPW Workshop API 当前主要向插件提供正在播放的歌词行。

默认单行模式只依赖公开回调。实验性多行歌词会尝试获取更完整的歌词时间轴，因此对宿主版本和内部行为更敏感。

如果实验性多行模式异常，关闭它即可回到更稳定的默认单行路径。

### 多歌词插件

同时启用多个会参与 SPW 歌词加载的插件时，宿主回调顺序可能影响本插件最终收到的歌词事件。

如果问题只在某个插件组合下出现，反馈时请注明同时启用了哪些歌词相关插件。

### 非 1× 播放速度

当前对 SPW 非 1× 播放速度的适配仍不完整。

调整倍速后，逐字动画和时间轴可能明显不同步。该问题已记录在 [Issue #15](https://github.com/GaBoron/Dynamic-Lyrics-Island-for-SPW/issues/15)。

排查普通歌词时序问题时，请先恢复到 1×。

## 本地歌曲、封面与总时长

插件不会访问 SPW 私有曲库数据库来补齐封面和时长，而是只读当前本地音频文件。

### 封面来源

按以下顺序尝试：

1. 音频文件内嵌封面；
2. 同目录 `cover.jpg`；
3. 同目录 `cover.png`；
4. 同目录 `folder.jpg`；
5. 同目录 `folder.png`。

网络歌曲、当前不可访问的文件或没有封面的歌曲会使用占位图。

### 总时长

展开后的进度条需要可靠的歌曲总时长。

本地音频通常可以读取；网络歌曲、不可访问文件或无法可靠解析时长的格式可能只能显示当前播放时间，而不能提供完整 seek 进度条。

歌词显示和上一首／播放暂停／下一首不会因此失效。

## 实时频谱与音频输出

Windows 实时频谱通过目标 SPW 进程及其子进程的音频回环获取四个频段值。

它不会读取：

- 麦克风；
- 其他应用的音频；
- 完整系统混音；
- 录音文件。

运行条件：

- Windows build 20348 或更高；
- 可用的 .NET Framework 4.x 运行环境；
- 共享模式音频输出。

独占模式、ASIO 或其他绕过共享音频链路的输出方式可能无法捕获。

实时捕获不可用时，词岛不会停止工作，而是切换到轻量模拟频谱并提示一次原因。

> [!NOTE]
> 低性能模式会主动停用实时音频捕获，因此此时看到模拟频谱是正常设计，不是故障。

## 快捷键

当前默认快捷键为 `Ctrl+Shift+D`，用于显示／隐藏词岛。

它只在 SPW 内生效，并不是系统级全局快捷键。

## Windows 界面限制

### 全屏检测

“全屏时隐藏”依赖前台窗口的全屏判断。

动态壁纸、桌面增强软件或其他覆盖整个屏幕的窗口可能被识别为全屏，从而让词岛隐藏。

### 字体

内置 Noto Sans SC 覆盖常用中英文、日韩汉字和多数界面符号，但极少数未收录字符仍可能显示缺字框。

指定系统字体后，如果某个字符缺失，会回退到内置字体。

## Linux 实验性支持

Linux 版本使用与 Windows 相同的大部分歌词和 Swing UI，但窗口运行在独立界面进程中。

### 运行环境

需要：

- Linux x64；
- 支持 Java / Swing 插件的 SPW Linux 宿主；
- `/usr/bin/python3`；
- GTK 3；
- X11 或 XWayland。

界面使用 SPW 自带 JVM，不需要另外安装 Java；Python helper 只使用标准库。

### 托盘

快捷设置通过 GTK 系统托盘提供：

1. 优先使用 AppIndicator / Ayatana AppIndicator；
2. 不可用时尝试 GTK StatusIcon。

不同桌面环境对托盘支持差异较大。如果桌面没有可见托盘区域，仍可以通过 SPW 原生插件设置页管理词岛。

### 当前未提供的 Windows 能力

Linux 当前不提供：

- SPW 进程实时音频频谱；
- 频谱取色；
- 鼠标穿透；
- 悬停自动隐藏；
- 前台全屏检测；
- Windows 式额外置顶强化；
- 词岛区域右键快捷菜单。

这些设置不会在 Linux 配置页中显示。已有 Windows 配置值会保留，之后切回 Windows 包仍可继续使用。

### 已知问题

拖动词岛后松开鼠标时，Linux 下可能短暂闪回原位置，再回到新位置。

X11、GNOME / KDE Wayland 与 wlroots 等桌面环境的行为仍可能存在差异，因此 Linux 支持目前仍标记为实验性。
