# 兼容性与限制

## 平台支持

| 平台 | 适配情况 |
| --- | --- |
| Windows | 完整支持所有功能 |
| Linux | 可构建实验包；需支持 Java/Swing 插件的 SPW Linux 宿主 |
| macOS | 暂无计划 |
| Android / iOS / HarmonyOS | Salt Player 暂不支持插件功能 |

## 歌词与宿主限制

插件只接收 SPW 已加载的歌词，不搜索、不上传，也不修改歌曲或歌词文件。SPW 当前仅提供正在播放的歌词行，因此无法预告下一句或显示完整歌词列表。

歌词换行时机由 SPW 决定。若其他插件提前返回歌词，SPW 是否继续通知本插件取决于宿主调用顺序。

## 音频与封面限制

- 实时频谱依赖 Windows build 20348 或更高版本的进程回环能力。
- 独占／ASIO 输出可能无法被捕获，建议使用共享模式音频输出。
- 频谱只捕获 SPW 进程及其子进程，不读取系统混音或麦克风。
- 封面只从本地音频标签或同目录 `cover.jpg`、`cover.png`、`folder.jpg`、`folder.png` 读取；网络歌曲或不可读文件使用占位图。

## 界面限制

- `Ctrl+Shift+D` 只在 SPW 内生效，不是系统全局快捷键。
- 动态壁纸可能被识别为全屏窗口，导致开启“全屏时隐藏”后词岛消失。
- 内置 Noto Sans CJK SC 覆盖常用中英文、日韩汉字及界面符号；未收录的特殊文字仍可能显示缺字框。

## Linux 实验包

Linux x64 词岛在独立界面进程中运行，通过匿名管道接收宿主播放快照和设置、回传播放与配置操作。宿主最小化时 Skiko 的 OpenGL 换帧可能阻塞其 EDT；独立进程不共享该 EDT 或 Java2D 队列。界面进程使用 SPW 自带的 JVM，通过标准 JNI Invocation API 启动，无需另装 Java，也不更改宿主渲染参数。

运行依赖 `/usr/bin/python3`（仅标准库）、GTK 3 与 X11/XWayland。Linux 快捷设置通过常驻托盘辅助进程提供，优先使用 AppIndicator／Ayatana AppIndicator，不可用时回退 GTK StatusIcon。右键托盘图标调用 GTK 系统菜单，保留勾选状态；词岛区域右键暂缓。插件停用或宿主退出时回收词岛进程，托盘辅助进程也会随父进程退出。

词岛显式使用 XRender 和 ARGB 画布，在内存中完成整帧后一次性提交。可见窗口不再随歌词换行／展开收起反复修改形状；X Shape 扩展只限制鼠标命中区域，透明空白不拦截点击。悬停区域保留边界，避免动画时反复进出。

Linux 尚未实现进程音频频谱、鼠标穿透、前台全屏检测和额外置顶强化。对应的实时频谱、频谱取色、鼠标穿透、悬停隐藏和全屏隐藏设置会从 Linux 配置页与右键菜单隐藏；左侧内容固定使用本地专辑封面。已有配置中的相关键会保留，回到 Windows 包后仍可继续使用。X11、GNOME/KDE Wayland 与 wlroots 环境仍需分别验证。

更多实现边界和 API 依据见 [开发与构建](development.md)。

已知问题：拖动词岛后松手可能短暂闪回原位置，再回到新位置，暂未修复。详见 [常见问题](troubleshooting.md#linux-已知问题)。
